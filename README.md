# Omadungeon

A rogue-like that steals its colours from your desktop.

Omadungeon reads whatever Omarchy theme you are running and builds the dungeon out of it.
Your accent colour lights the torches. Your wallpaper decides the shape of the floor you
are about to walk into. Change theme mid-run and the stone retints around you while you
are standing on it.

The enemies are the people who have opinions about your setup: clowns, greybeards and
tinkerers.

Runs are short and fast, in the spirit of *Tiny Rogues*. Rooms lock behind you until they
are clear, a chest opens after every fight, and a build comes together out of stats,
procedural loot and a handful of abilities you actually chose. Nine floors, three biomes,
a boss on every third.

It is playable and it is not finished. Expect rough edges.

## Install

### Arch

Grab `omadungeon-<version>-x86_64.pkg.tar.zst` from the
[latest release](https://github.com/ferrreo/omadungeon/releases/latest) and install it:

```bash
sudo pacman -U omadungeon-*-x86_64.pkg.tar.zst
```

Then run `omadungeon`, or find it in your launcher.

If you would rather build it yourself, the `PKGBUILD` in `packaging/` builds from a
release tag:

```bash
cp packaging/PKGBUILD . && makepkg -si
```

### AppImage

One file, no install, works on anything glibc-based:

```bash
chmod +x Omadungeon-x86_64.AppImage
./Omadungeon-x86_64.AppImage
```

If your distro has dropped FUSE 2 and it refuses to start, either install `fuse2`, or
extract and run it directly:

```bash
./Omadungeon-x86_64.AppImage --appimage-extract
./squashfs-root/AppRun
```

### Debian, Ubuntu, PikaOS

There is a `.deb` on the release page. You know what to do with it.

## Your desktop is the level generator

| What it reads | What it does with it |
|---|---|
| `~/.local/state/omarchy/current/theme/colors.toml` | Every colour in the dungeon |
| `~/.local/state/omarchy/current/background` | Seeds generation — room shapes, sizes, hazards |
| `~/.config/otter-shell/theme.conf` → `colors_path` | Colours, when you are on otter-shell instead |
| `$XDG_RUNTIME_DIR/otter-shell/wallpaper-state` | otter-wallpaper's current wallpaper |
| The bundled Omarchy Radio tracks | The light, and the density of a floor |

Two rules keep it honest. **The theme is the only thing that says what colour the dungeon
is** — the wallpaper never tints anything, it shapes the run. And **every lit pixel has
something in the room casting it**: torches, the motes drifting off your own character,
spells, a chest. There is no ambient light and no full-screen wash, so the dark corners
are really dark.

The music moves the torches rather than the screen. A loud passage burns them brighter
and wider; a quiet one lets the room close in. It follows the track's envelope through a
hard rate cap, so it drifts — it never pulses, flashes or strobes.

None of this is required. With no Omarchy and no otter-shell it falls back to a built-in
palette and plays fine.

## Playing it

Four classes — Fighter, Ranger, Wizard, Oligarch — each with their own weapon, dodge,
innate passive and class ability. Two active slots and two passive slots to fill as you
go.

Keyboard and mouse or a controller, both first class; the whole game including every menu
is playable pad-only. Quitting is safe — a run resumes at the room you left.

Press <kbd>Tab</kbd> (or Back on a pad) at any time to see your build: both abilities with
their cooldowns, both passives, every gear slot and the full stat sheet with the sources
of each number.

## Building from source

Needs Godot 4.7 and Python 3.

```bash
godot --headless --path . --import          # first time only
tools/export.sh "Linux x86_64"              # -> export/linux/omadungeon
tools/deb.sh full                           # -> dist/*.deb
tools/appimage.sh                           # -> Omadungeon-x86_64.AppImage
```

Tests run headless and never open a window on your session:

```bash
tools/test.sh -c                            # the gate
tools/run-checks.sh verify                  # what the rendered checks last recorded
```

`tools/run-scenario.sh` and `tools/capture-scene.sh` drive the real game inside a nested
headless compositor and screenshot it, which is where the pictures in `tests/out/` come
from.
