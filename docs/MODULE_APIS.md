# Module APIs (generated from builder reports)

Reference for integration. Verify against source before relying on a signature.

The headings used to carry each module's test count. They were a snapshot of one build and
nobody re-counted them, so they aged into a number that looked authoritative and was not: run
`tools/test.sh -c` (optionally `-a res://tests/unit/<dir>`) for the counts that are true today.

The **Incomplete** note under each module was written by that module's builder, before the
modules were wired together. They were re-checked against the integrated build and rewritten
where reality had moved on; the cross-module blockers every builder hit (the `Projectile.gravity`
parse error, the `Room` / `FloorData.Room` class-name collision, and the gdUnit discovery abort
they caused) are all fixed and are no longer listed. What is left under each heading is what is
genuinely still open.

**Integration:** 1. Autoload order in project.godot: EventBus, GameState, Desktop, SaveManager, Audio, Music, RunManager, UiNav, Quit. The script intentionally has no class_name (a class_name equal to an autoload name shadows the singleton). Tests instantiate it via preload("res://src/core/save_manager.gd").new() and override run_path/profile_path before add_child.
2. RunManager wiring (already in src/core/run_manager.gd): `SaveManager.state_provider = build_run_state` in _ready(); room_cleared/floor_started already schedule autosaves (do not double-wire); extra request_autosave() after chest/equip/altar changes is fine (the debounce collapses them). build_run_state() should also fill `gen_params`, `tracks_played` (from Music) and optionally `rng_states`.
3. Resume: Title shows Continue when `SaveManager.has_run()` (never by testing FileAccess.file_exists("user://run.json"): that shows a dead button for a corrupt/future file and hides a recoverable .tmp). RunManager: `var state := SaveManager.load_run()`, null = nothing to resume; load_run() also primes the counter feeds (restored gold is not "earned", the resumed floor is never flawless).
4. Run end: `SaveManager.delete_run()` then `SaveManager.record_run_end(victory, floor_index, class_def.id, Desktop.palette.name)` with the 0-based floor_index; Abandon Run does the same. Deaths are recorded automatically; call record_death(id) only to override.
5. Counters other modules feed via `SaveManager.increment(&"...")`: clowns_killed / greybeards_killed / tinkerers_killed (enemy death by faction). Profile writes from increment() are lazy unless a rule fires, which saves immediately.
6. UI gating (still to be wired by the UI/abilities modules): ClassSelect must disable oligarch with `not SaveManager.is_unlocked(&"oligarch")`; ability offers must filter with `SaveManager.is_unlocked(ability.id)` (every non-gated id returns true); the toast layer must connect `EventBus.unlock_earned(id: StringName, title: String)` to show "Unlocked: <title>". Stats page reads SaveManager.profile.
7. Do not put the debounce on a Timer node in a paused tree: SaveManager uses _process with PROCESS_MODE_ALWAYS so Save & Quit from the pause menu still flushes.

**Incomplete:** Nothing. Every hand-off this module was waiting on has landed: `RunManager` is the last autoload in project.godot and sets `SaveManager.state_provider = build_run_state`; `src/ui/title.gd` asks `SaveManager.has_run()` (the `FileAccess` check survives only as a fallback when the autoload is absent, e.g. in isolated UI tests); `src/main.gd` and `src/items/chest_offers.gd` filter offers through `SaveManager.is_unlocked()` and `src/game.gd` toasts `EventBus.unlock_earned`; and `build_run_state()` fills gen_params, tracks_played and rng_states. (`floors_music` is gone: it was serialized into every run.json and never written by anything.)

## gen

Pipeline entry: `FloorGenerator.generate(params: GenParams, rng: RandomNumberGenerator) -> FloorData` (static; runs archetype -> graph -> layout -> loops -> corridors -> dressing -> fill -> validate, retries up to 20 times with an rng-derived reseed, push_error + best attempt on total failure; deterministic: same params+seed -> identical layout_hash()). `FloorGenerator.generate_once(params, rng) -> FloorData` (single pass, null on placement/carve failure).

`LanternAnchors` (RefCounted, docs 5.1 #8): `place(data, spacing, rng) -> Array[Vector2i]` fills `FloorData.lantern_anchors` - WALL tiles along every room ring side and every corridor wall, one per `spacing` tiles (`Biome.lantern_spacing`, 10-18 by biome, `DEFAULT_SPACING` 11, never under `MIN_SPACING` 3; wide, so light is a local event and not wallpaper), each side's phase rolled separately so a room lights one or two of its walls rather than all four, at least one per *room* that has a legal tile, never within `DOOR_CLEARANCE` (2, Chebyshev) of a DOOR tile, never two within `MIN_APART` (2); every anchor has a walkable 4-neighbour. Helpers: `door_zone(data) -> Dictionary` (the excluded tiles), `ring_sides(room) -> Array[Array]` (top, right, bottom, left without corners), `is_anchor_tile(data, p, forbidden)`. Called last in `FloorGenerator.generate_once`, on the floor's rng, so the list is part of `layout_hash()` and identical on a regenerated floor. The tile contract it rests on is the `FloorData.Tile` doc comment (VOID outside, WALL solid everywhere it stands, FLOOR/CORRIDOR/DOOR walkable, PIT a hole).

`FloorArchetype` (RefCounted, docs 5.1 #1): ids `HUB/WINDING/RING/GRID/CAVERN` (`ALL`); `resolve(params, rng)` rolls one (one rng draw, honours `params.archetype` when it names one), `weights(params)` the roll weights (biome `BIOME_WEIGHTS`, then `room_size_bias`, `corridor_wiggle`, tempo and energy tilt them, every weight > 0), `by_id(id)` (null for unknown). Knobs the pipeline reads: `spine_share`, `branch_style` (any/spine/hub), `max_branch_depth`, `has_hub`, `loop_delta`, `closes_ring`, `loop_max_gap`, `dir_style` (uniform/snake/curl/spoke), `gap_delta`, `size_weight(class)`, `transpose_chance`, `shape_weight(shape)`, `wide_share`/`chamber_share`/`alcove_share`. `static var forced` is the capture hook (`--scenario-archetype`), copied into `GenParams.archetype` by `GenParams.build`.

`RoomShape` (docs 5.1 #2): ids `RECT/L_SHAPE/T_SHAPE/CROSS/OCTAGON` (`ALL`); `pick(type, size, arch, rng)`, `fits(shape, size)` (cuts need 11x9, octagon a 7 short side), `cut_tiles(shape, rect, variant) -> Array[Vector2i]` (the interior tiles that become WALL; the centre 3x3 is never cut), `stamp(data, room, variant)`, `floor_count(shape, rect)`. `FloorLayout._build_data` stamps every room before corridors are carved, so `CorridorCarver._door_ok` (the tile behind a door must be FLOOR) keeps doors off the cuts.

`RoomBudget` (docs 5.1 #4): `TABLE` (one row per floor: altar chance, shop chance, elite/trap/treasure chance), `for_floor(i)`, `shop_guaranteed(i)`, `max_count(i, type)` (1 or 0 for SHOP and the optional types), `roll(floor_index, ordinary, rng) -> Array[int]` (the types of the non-structural rooms: blessing first, shop if rolled, then optionals within `FloorGraph.combat_quota`, COMBAT for the rest). `FloorGraph._assign_types` and `SimFloorPlan.build` both roll through it; `FloorValidator._check_types` enforces it.

`CorridorDressing` (docs 5.1 #3): `apply(data, owners, arch, rng)` after every corridor is carved and before the wall ring - widens (`_widen`), adds a 5x3 chamber (`_chamber`, all-or-nothing) or a 2-deep alcove (`_alcove`); `is_safe(data, owners, p, index)` opens a VOID tile only when every non-wall 8-neighbour belongs to corridor `index` (the carver's `owners` map: CORRIDOR and DOOR tile -> corridor index). Opened tiles go on `FloorData.Corridor.extra`.

`ArenaSpawns` (docs 7.4): `place(room, candidates) -> Array[Vector2i]` (index 0 the boss's tile: deepest along the nearest door's inward normal, nearest the centre line, `WALL_INSET` 2 off the wall, `DOOR_CLEARANCE` 8 from every door; then up to `PACK_SPOTS` 3 pack tiles around it, `PACK_SPACING` apart), `door_distance(doors, p)`. `RoomFiller._place_spawns` calls it for BOSS rooms; `FloorValidator._check_arena_spawns` refuses a closer spawn.

`GenParams` (RefCounted): floor_index, room_count, `archetype: StringName` (forced plan, empty = roll; saved/restored with the rest), corridor_wiggle, room_size_bias, trap_density, prop_density, biome: StringName, is_boss_floor, extra_loops (1..3), enemy_count_scale (`MusicLevers.foes_calm..foes_loud` from music energy), ambush_scale (TRAP-room pack size), light_scale (multiplier `FloorRoot.light_scale` puts on the ambient), sight_scale/cadence_scale/loot_scale (handed to every regular enemy by `FloorPopulator`), accent_prop (index of the track's signature prop kind, -1 in silence; `static accent_prop_for(track_hash)`), music_energy, music_tempo, track_hash, wallpaper_seed, ambient (0.55..1.0 floor light level), theme_hash, fill_bias_hash. All of the music-derived fields are saved and restored by `FloorRestore.gen_params_to_dict/gen_params_for`. `GenParams.build(profile: ThemeProfile, floor_index: int, music: MusicProfile = null, wallpaper: WallpaperAnalyzer.Result = null)` is the full entry point — energy scales enemy count and prop density, tempo shifts corridor_wiggle around the theme's own value by up to TEMPO_PUSH 0.2 either way (an offset, not a lerp toward the tempo - a lerp collapses every theme onto one number; ignored when tempo is 0), the track hash and the wallpaper's image-path hash join theme_hash in `fill_bias_hash`, the wallpaper's Sobel edge density shifts prop_density by at most ±0.15, and its top-third luminance becomes `ambient`. `GenParams.from_profile(profile, floor_index, music_energy := 0.5)` is the energy-only convenience wrapper (identical output to the old behaviour). `template_bias(template_id) -> float` (0.75..1.35) is the fill-template tie-break RoomFiller multiplies weights by; `refresh_fill_bias()` after restoring saved hashes. `hazard_weights: Dictionary` (copied from `ThemeProfile.hazard_weights`, saved and restored with the rest) and `trap_kind_weight(kind) -> float` are what `RoomFiller._pick_kind` rolls trap kinds with; `room_gap_extra() -> int` (0..5) is the extra room spacing FloorLayout adds to MIN_GAP, from corridor_wiggle *and* room_size_bias; `dithered_int(value, key)` rounds with a per-theme dither so neighbouring themes do not collapse onto one integer. `FloorGenerator.layout_seed(seed, params)` folds theme_hash into the layout seed (identity on a params with theme_hash 0), which is what makes the same seed under a different theme a different dungeon (docs 5.1). Statics `room_count_for(i)` (7,8,9,10,11,12,12,13,13), `is_boss_floor_index(i)` (2,5,8), `biome_for_floor(profile, i)` (0-2 crypt, 3-5 profile.biome_middle_id(), 6+ void).

`Biome` (Resource, data/biomes/<id>.tres): id, display_name, floor_min/max, trap_kinds: Array[StringName], prop_kinds: Array[StringName], palette_keys: PackedStringArray, tileset_path ("res://assets/tiles/<id>.png"), fill_templates, hazard_weight. `Biome.load_by_id(id) -> Biome` (cached by ResourceLoader; falls back to a default with push_warning), `allows_trap(kind)`, `allows_template(id)`. `Biome.ALL_IDS`.

`RoomTemplate` (Resource, data/rooms/<id>.tres): id, pattern (empty|pillars|cross|ring|rubble|pits), weight, `biome_weights: Dictionary` (biome id -> multiplier; `weight_in(biome_id)` is what `RoomFiller` rolls with), min_size, allowed_types: Array[int] (RoomType values), allowed_biomes, spacing, density, optional `mask` string ('.' floor '#' wall '~' pit 'o' prop) stamped centred. `fits(size, type, biome_id)`.

`FloorGraph` (RefCounted): `build(params, rng, arch := null)` (a null `arch` rolls one), `archetype`, `hub_id` (-1 unless the hub archetype), inner class `RoomVertex {id, type, neighbors, parent, depth, distance, on_spine, branch_depth}`, `nodes`, `tree_edges`, `loop_edges`, `start_id`, `stairs_id`, `boss_id` (stairs_id == boss_id on boss floors), `loop_target(params)` (theme loops + archetype delta, 0..`MAX_LOOPS` 4), `tree_degree_cap(id)` / `degree_cap(id)` (the hub takes `FloorArchetype.HUB_MAX_DEGREE` 5), `add_loops(candidates, max_count, rng)` (a ring archetype spends its first loop on the spine-closing pair), `compute_distances()`, `bfs_order()`, `all_edges()`, `count_type(type)`, `apply_to(data)` (also writes `data.archetype`). Guarantees: exactly one ALTAR|SHRINE, SHOP per `RoomBudget`, >= 60% fights (COMBAT/ELITE/TRAP) among the free pool, 0-1 ELITE/TRAP/TREASURE where the budget allows them, stairs graph_distance >= 3, boss floors: spine start -> 2-3 rooms -> BOSS (leaf, single door), side rooms at branch depth <= 2, loops never touch BOSS or shorten the stairs path below 3.

`FloorLayout`: `place(graph, params, rng) -> FloorData|null` (grid-tree placement steered by `arch.dir_style`, 50 attempts, `SIZE_CLASSES` closet 7x5 / small 9x7 / medium 13x9 / large 17x13 / hall 21x9 / gallery 17x7 plus arena 21x15 and hub 23x17, via `size_for(type, bias, rng, arch := null)` and `fight_size_weights(bias, arch)`; rooms may be transposed; every room gets a `RoomShape` stamped; >= 3 wall tiles between interiors plus `arch.gap_delta`, grid <= 160x120), `loop_candidates(data, graph, max_gap := 14)`. Constants MAX_WIDTH/MAX_HEIGHT/SIZE_*.

`CorridorCarver`: `carve_all(data, edges, optional_edges, params, rng, arch := null) -> bool` (AStarGrid2D through VOID with wiggle-scaled jitter weights; sets DOOR tiles, `room.doors[neighbor_id] = door_tile`, CORRIDOR tiles, FloorData.Corridor entries with path exclusive of door tiles, then `CorridorDressing.apply`, then WALL ring around corridors), `pick_door(data, room, other, wiggle, rng)` (a door's inside tile must be FLOOR).

`CompositorWindow` (RefCounted, `src/desktop/compositor_window.gd`) — the window manager asked
whether **this process's** window is fullscreen, which on Wayland the engine cannot see.
Tunables in `data/desktop/compositor.tres` (`CompositorProfile`: `poll_seconds`,
`query_timeout_seconds`).

- `enum Kind { NONE, HYPRLAND, SWAY }`, `enum State { UNKNOWN, WINDOWED, FULLSCREEN }`.
- `static detect_kind() -> Kind` — from `HYPRLAND_INSTANCE_SIGNATURE` / `SWAYSOCK`; `NONE` when
  headless (a process with no surface has nothing for a compositor to describe).
- `static query_argv(kind) -> PackedStringArray` — `hyprctl clients -j`, `swaymsg -t get_tree -r`.
- `static parse_state(kind, text, pid) -> State` — matches on pid, so it answers about the game's
  own window and not the focused one. Hyprland's `fullscreen` is read as a mode (bit 2; 1 is
  *maximised*, which is not fullscreen) and as the pre-0.42 boolean; sway's `fullscreen_mode > 0`,
  walking `nodes` **and** `floating_nodes`. No matching window → `UNKNOWN`.
- `static run_query(kind, pid, timeout_seconds) -> State` — one blocking query; any failure is
  `UNKNOWN`. `static timeout_prefix(seconds)` puts `timeout(1)` in front when the system has it.
- `poll(delta)` — collects the finished query and starts the next when due, on
  `WorkerThreadPool`; `state` is the last answer; `is_active()` is false for `Kind.NONE` and
  under a test run. `invalidate()` drops the cached answer (call it whenever the *game* moves its
  own window). `shutdown()` waits for a query in flight — call it before dropping the object.
- `align_engine_mode(window, engine_says_fullscreen) -> bool` — writes the compositor's truth into
  `window.mode` so the engine has something to change. Godot's Wayland backend only sends the
  difference between the mode it believes it is in and the one asked for, so a window the
  compositor fullscreened behind its back never receives an `unset_fullscreen`.

### The rule a controller fix rests on: a scrolled list needs an explicit focus chain

Godot falls back to a **geometric** neighbour search only when `focus_neighbor_*` is empty, and
that search **refuses a control its container has clipped** - which is every row below the fold
of a `ScrollContainer`. So a pad walking a scrolled list stops dead at the last row that happens
to fit: `ui_down` finds no neighbour, focus never moves, and the list never scrolls, because
nothing scrolls a list until focus has moved into it. `ScrollContainer.follow_focus` does not
fix this; it only reacts after focus has already moved. Thirteen rebind rows in two columns were
unreachable on a pad for exactly this reason.

An **explicit** neighbour is checked for visibility and focus mode and nothing else - clipping is
not consulted - so a wired chain walks into the clipped part of the list and the list scrolls
afterwards, because focus moved. That is the order a scrolled list has to work in, and it is why
`UiFocusChain` exists rather than a `follow_focus` flag. Any new list that scrolls owes itself a
chain; write this down again if you are tempted to delete it.

## feel

GameFeel (Node, `class_name GameFeel`, src/core/feel/game_feel.gd; one node named "GameFeel" under the tree root, process mode ALWAYS): static instance(tree)->GameFeel, static of(node)->GameFeel. Hit-stop is counted in **rendered frames**, not seconds, and queued rather than summed: request_hit_stop(frames, scale=-1)->bool takes the longest pending stop (capped by profile.hit_stop_max_frames) and is refused while the post-stop refractory window runs, so a flurry cannot chain freezes; hit_stop_for(amount, heavy=false), hit_stop_seconds(seconds, scale=-1) (what HitStop.apply routes through), is_frozen(), hit_stop_frames_left(), refractory_frames_left(), restore_time(). slow_motion(scale, seconds) is the separate, rarer beat (the room-ending blow) and ignores the refractory window. Shake is trauma-based: add_trauma(amount 0..1, duration=0) (a duration only makes it decay faster), shake(strength_px, duration) (the `EventBus.screen_shake` adapter — GameFeel connects to that signal itself, so nothing else should), trauma(), is_shaking(), shake_offset()->Vector2 (already pixel-snapped, `max_offset * trauma²`, resampled at profile.shake_frequency), punch(dir, strength)/punch_offset() (strongest kick wins, never summed), reset_shake(), reset(). Flashes: flash_scale() (peak strength after `reduced_flash`), flash_time(), flash_modulate(item, strength)->Tween, reduced_flash(). Gates: `enabled` (master), `hit_stop_enabled` (hit-stop + room-clear slow only; `HitStop.set_enabled` and the `reduce_motion` setting toggle this), shake_allowed() (false when `screen_shake` is off or `reduce_motion` is on). Room-ending blow: connects EventBus.enemy_died + room_cleared and only fires the slow when the clear lands within profile.room_clear_window_frames of the last death (room_ending_blow_pending() exposes that).

FeelProfile (Resource, data/feel/feel.tres; static load_default()): every tunable number — hit_stop_scale/light_frames/heavy_frames/max_frames/refractory_frames, heavy_damage, trauma_light/heavy/death, trauma_decay, shake_max_offset, shake_frequency, look_ahead_px, look_ahead_speed, punch_px, punch_decay, flash_time, flash_strength, reduced_flash_scale, death_burst_count, room_clear_slow_scale/time, room_clear_window_frames, tell_pulse_hz, tell_alpha_min/max, puff_count, puff_lifetime, trail_count, trail_lifetime. Helpers hit_stop_frames(amount, heavy) and hit_trauma(amount, heavy).

DangerTell (RefCounted, static): the one visual language for "this will hurt", shared by enemy windups and trap arming. ROLE (&"danger"), FALLBACK, RING_START, RING_WIDTH, AREA_ALPHA_SCALE, MARK_STEM/MARK_DOT, URGENCY_BOOST; color(), pulse(elapsed, hz=-1), urgency(elapsed, total), alpha(elapsed, total, prof=null), tinted(...), ring_radius(elapsed, total, radius), breathe(elapsed, hz), default_profile(). `TrapBase.TELL_PULSE_HZ` and its 0.15..0.5 alpha band are the same numbers; tests/unit/feel/danger_tell_test.gd locks the two together, so a trap tell and an enemy windup can never drift apart. Making `TrapBase` read `DangerTell` directly is a one-line follow-up for the traps module.

FxPool (Node2D, "FxPool" under the tree root): static instance(tree)/of(node); puff(pos, tint, count=-1, radius=14)->CPUParticles2D (one-shot impact), trail(target, tint, radius=6)->CPUParticles2D (follows `target` and keeps draining after it is freed), release(emitter), prewarm(count), clear() (also runs on EventBus.floor_started), active_count(), idle_count(), allocations() (flat once the high-water mark is reached — that is the contract), static dot_texture().

HitStop (RefCounted facade, src/player/hit_stop.gd): NODE_NAME (== GameFeel.NODE_NAME), DEFAULT_DURATION, DEFAULT_SCALE; apply(tree, duration, scale), frames(tree, count), set_enabled(tree, on), is_active(tree). Kept so `AbilityFx.hit_stop` and `SettingsPanel.apply_motion_policy` keep working unchanged.

**Integration:** (a) Emit `EventBus.screen_shake(px, seconds)` as before — GameFeel converts it to trauma; do not also call `PlayerCamera.shake()` for the same event. (b) PlayerCamera reads `GameFeel.shake_offset() + punch_offset()`, clamps to its `max_shake` export and rounds; it also leads the aim by `look_ahead_px` for any follow target exposing `aim_direction() -> Vector2` (`look_ahead_scale = 0` switches that off per camera). (c) WeaponController melee runs `Phase {READY, ANTICIPATION, IMPACT, RECOVERY}` (`phase()`, `is_in_recovery()`, `cancel_recovery()`); the hitbox is live from the first anticipation frame, so a committed swing is never eaten, and `cancel()`/a dodge/a weapon skill cut the recovery short. (d) Projectile borrows a pooled trail in `_ready` (`trail_enabled`) and pops a pooled puff in `_expire` (`impact_puff`); set either export false for shots that carry their own FX. (e) EnemyBase exposes hit_freeze_frames(amount) and death_burst_count(); its hit flash, squash threshold and death burst all come from the profile.

**Incomplete:** (1) `AbilityFx.flash` (src/abilities) still flashes at full strength and does not consult `GameFeel.flash_scale()`, so the `reduced_flash` setting does not dim ability FX — a two-line change in the abilities module. (2) `TrapBase` duplicates the tell numbers instead of reading `DangerTell` (locked by a test, see above). (3) The `combat` rendered scenario never happens to catch an enemy mid-windup, so the tell is verified by its own native-resolution capture, `tests/unit/feel/tell_capture.tscn` -> `tests/out/feel_tell.png`, rather than by an in-game screenshot.
